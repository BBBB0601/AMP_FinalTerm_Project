## 1. 팀원별 R&R 및 핵심 파트 분담

첫 팀 프로젝트의 부담을 줄이기 위해, **초반에는 서로의 코드를 건드리지 않고 각자 독립된 개발 환경(Android Studio / Unity)에서 단독 모듈을 구현**한 뒤, 중반에 약속된 JSON 규격으로 연결하는 방식으로 구성합니다.

| 담당자 | 담당 레이어 | 개발 환경 | 핵심 역할 및 담당 요구사항 |
| :--- | :--- | :--- | :--- |
| **최주환** | Android Native | Android Studio (Kotlin, Jetpack Compose) | 네이티브 UI(SCR-001, 003, 004), 텍스트 정규식 파서, Room DB, 화면 캡처 공유 [`SFR-001`, `SFR-007`, `INR-001`] |
| **김기현** | Unity 3D Engine | Unity Editor (C#) | 절차적 1:1 박스 메시 동적 생성, 실시간 OBB 충돌 판정, 60cm 동선 가이드라인 [`SFR-003`, `SFR-005`, `SFR-006`] |
| **진승호** | Unity AR & Bridge | Unity / Android Studio | ARCore 바닥/벽면 인식, 앵커링 조작, UaaL 모듈화 익스포트 및 IPC 양방향 통신 브릿지 [`SFR-002`, `SFR-004`, `PER-001`, `COR-001`] |

## 2. 모듈 간 데이터 통신 규격 (JSON 사전 합의)

> [!IMPORTANT]
> 최주환(Android) $\rightarrow$ 진승호(Bridge) $\rightarrow$ 김기현(Unity)으로 전달되는 핵심 데이터 모델입니다. 이 규격을 확정해두면 세 사람이 각자 독립적으로 개발을 진행할 수 있습니다.

### [Android -> Unity] 가구 치수 전송 규격 (`FurnitureConfig`)
* **호출 방식:** `UnityPlayer.UnitySendMessage("ARBridgeManager", "OnReceiveFurnitureData", jsonString)`
```json
{
  "name": "원목 단독 책상",
  "width": 1.20,
  "depth": 0.60,
  "height": 0.75,
  "unit": "meter"
}
```

### [Unity -> Android] 충돌 상태 피드백 규격 (`CollisionEvent`)
* **호출 방식:** JNI 콜백 함수 `OnCollisionStateChanged(boolean isColliding)`
```json
{
  "isColliding": true,
  "target": "WALL",
  "message": "벽면 침범 발생"
}
```

### [Phase 1] 개별 독립 모듈 구현 (로컬 단독 작업)
* **목표:** 타 팀원 작업과 의존성 없이, 각자 맡은 영역의 핵심 코드를 로컬에서 1차 완성한다.

#### 파트 A. 안드로이드 네이티브 UI 및 로직 (담당: 최주환)
- [ ] **[SCR-001] 가구 치수 수동 입력 폼 UI 구현**
  - 가구 이름, 가로(W), 깊이(D), 높이(H) TextField 레이아웃 (Jetpack Compose)
  - $10\text{cm} \le W, D, H \le 300\text{cm}$ 수치 유효성 검증 로직 구현
- [ ] **[SCR-001] 당근마켓 거래글 정규표현식 파서 작성**
  - 클립보드 텍스트 붙여넣기 버튼 구현
  - 정규식 `([0-9.]+)\s*(?:cm|x|X|\*|가로|세로|높이|폭)` 기반 치수 자동 분리 추출 로직 구현
- [ ] **[SCR-001] 자주 찾는 가구 프리셋 선택 컴포넌트**
  - 책상($120 \times 60 \times 75$), 서랍장($80 \times 40 \times 90$), 소형 냉장고($47 \times 50 \times 85$) 프리셋 카드 클릭 시 입력창 자동 완성
- [ ] **[데이터 모델] FurnitureConfig 데이터 클래스 및 JSON 직렬화**
  - $\text{cm} \rightarrow \text{m}$ 단위 환산 로직 및 Gson/Kotlinx Serialization 직렬화 함수 작성

#### 파트 B. 유니티 절차적 메시 및 충돌 판정 (담당: 김기현)
- [ ] **[SFR-003] $1:1$ 스케일 절차적 육면체 메시(Procedural Cube Mesh) 생성기**
  - $W, D, H$ 파라미터를 입력받아 정점 8개와 삼각 폴리곤 인덱스를 계산해 동적 Mesh 생성하는 C# 스크립트 작성
  - 실제 실내 배경을 가리지 않는 반투명 머티리얼 및 와이어프레임(Wireframe) 셰이더 적용
  - 생성된 메시에 맞춰 `BoxCollider` 컴포넌트 동적 크기 할당
- [ ] **[SFR-003] 바운딩 박스 외곽 실측 치수 라벨 렌더링**
  - 생성된 큐브의 가로, 높이 모서리에 실제 치수($120\text{cm}$, $75\text{cm}$)를 표시하는 3D 월드 TextMesh 렌더링
- [ ] **[SFR-005] OBB(Oriented Bounding Box) 실시간 간섭 검사 로직**
  - 가구 콜라이더와 가상 벽면/장애물 간의 교차 판정 로직 작성
  - 충돌 시 머티리얼 컬러를 안전(청록색 반투명)에서 위험(붉은색 발광)으로 즉시 전환하는 셰이더 프로퍼티 제어

#### 파트 C. 유니티 AR 기반 공간 인식 및 앵커링 (담당: 진승호)
- [ ] **[SFR-004] AR Foundation 및 ARCore 환경 세팅**
  - AR Session, XR Origin, ARPlaneManager, ARRaycastManager 컴포넌트 구성
  - 실제 바닥면(Horizontal) 및 벽면(Vertical) 평면 감지 및 평면 시각화 프리팹 연동
- [ ] **[SFR-004] 바닥 평면 조준 레티클(Reticle) 및 히트테스트**
  - 화면 중앙에서 바닥 평면으로 실시간 AR Raycast 발사하여 조준점(Reticle) 렌더링
- [ ] **[SFR-004] ARAnchor 기반 가상 객체 고정 및 제스처 조작**
  - 사용자가 지정한 위치에 객체를 고정하여 카메라가 움직여도 이탈하지 않도록 `ARAnchor` 바인딩
  - 1손가락 드래그(바닥 수평 이동), 2손가락 트위스트 제스처(Y축 회전) 구현

### [Phase 2] 모듈 간 결합 및 UaaL IPC 브릿지 연동 (통합 작업)
* **목표:** Unity 내부 모듈을 하나로 합치고, Android Studio와 Unity 간 데이터 송수신을 검증한다.

#### 1. Unity AR 캔버스 내부 통합 (김기현 + 진승호)
- [ ] **[통합 씬 구성] AR 평면 상에 절차적 가구 생성 결합**
  - 진승호의 AR 평면 인식 레티클 위치에 김기현의 절차적 큐브 메시가 정확히 스냅(Snap)되어 생성되도록 결합
- [ ] **[SFR-006] 전면 60cm 통행 동선(Clearance) 가이드라인 오버레이**
  - 가구 전면 방향 벡터 기준 폭($W$) $\times$ 깊이($60\text{cm}$) 크기의 바닥 점선 그리드 평면 데칼 렌더링
- [ ] **[SCR-002] AR 뷰 인터랙션 제어 툴바 연결**
  - 배치 고정 / 재배치 버튼 및 동선 가이드라인 표시 On/Off 토글 기능 연동

#### 2. UaaL 하이브리드 IPC 브릿지 구축 (진승호 + 최주환)
- [ ] **[UaaL] Unity 프로젝트의 Android 라이브러리(AAR) 익스포트 설정**
  - Unity Build Settings에서 "Export Project" 수행 후 안드로이드 스튜디오 `unityLibrary` 모듈로 임포트
- [ ] **[SFR-002] Android $\rightarrow$ Unity 단방향 치수 전달 검증**
  - Android 네이티브의 `AR 공간 확인하기` 버튼 클릭 시 `UnityPlayer.UnitySendMessage` 호출
  - Unity 내 `ARBridgeManager.cs`에서 JSON 수신 및 가구 자동 생성 확인
- [ ] **[SFR-002] Unity $\rightarrow$ Android 역방향 피드백 전달 검증**
  - Unity에서 충돌 발생 시 JNI Interface를 통해 Android 콜백 호출
  - Android 상단에 "벽면 침범 발생" 경고 배너 표시 및 기기 햅틱 진동(Vibration) 피드백 작동 확인

## 4. 첫 팀 개발 협업 가이드 (팀원 안내용 요약)

1. **초반에는 각자 로컬에서 테스트하기:**
   - 안드로이드 담당자는 유니티가 없어도 가짜(Mock) JSON 로그를 찍으며 UI를 완성할 수 있습니다.
   - 유니티 담당자는 안드로이드 연결 전 에디터에서 임의의 $W, D, H$ 값을 인스펙터 창에 넣어보며 큐브 생성과 충돌을 먼저 테스트합니다.
2. **단위 통일 필수 ($\text{m}$ vs $\text{cm}$):**
   - 사용자 UI 입력은 $\text{cm}$ 단위이지만, **유니티 엔진의 1단위는 $1\text{m}$** 입니다.
   - 따라서 안드로이드에서 유니티로 넘길 때 **반드시 $100$으로 나눈 미터 단위($120\text{cm} \rightarrow 1.2\text{m}$)** 로 변환하여 전송합니다.
3. **가동 부위(문짝 열림)는 과감히 제외:**
   - 교수님 피드백 및 요구사항 분석서 명세대로 문짝 회전 애니메이션은 이번 구현 범위에서 제외되었으므로, **"가구 전체 크기의 직육면체 박스 충돌"** 에만 집중합니다.
