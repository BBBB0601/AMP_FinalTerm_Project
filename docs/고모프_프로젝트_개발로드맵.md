## 1. 팀원별 R&R 및 핵심 파트 분담

첫 팀 프로젝트의 부담을 줄이기 위해, **초반에는 서로의 코드를 건드리지 않고 각자 독립된 개발 환경(Android Studio / Unity)에서 단독 모듈을 구현**한 뒤, 중반에 약속된 JSON 규격으로 연결하는 방식으로 구성합니다.

| 담당자 | 담당 레이어 | 개발 환경 | 핵심 역할 및 담당 요구사항 |
| :--- | :--- | :--- | :--- |
| **최주환** | Android Native | Android Studio (Kotlin, Jetpack Compose, Coroutines & Flow, Room DB + KSP) | 네이티브 UI(`SCR-001, 003, 004`, `Saved Layouts` Home 하위 통합), 텍스트 정규식 파서, Room DB(명칭·치수·기존/신규 구분 메타데이터), 화면 캡처 공유(`Intent & FileProvider`) [`SFR-001`, `SFR-007`, `INR-001`] |
| **김기현** | Unity 3D Engine | Unity Editor (C# / URP) | 절차적 1:1 박스 메시 동적 생성(12개 모서리 와이어프레임·치수 라벨), 실시간 OBB 충돌 판정, 가구 외곽 기준 60cm 동선 가이드라인 [`SFR-003`, `SFR-005`, `SFR-006`] |
| **진승호** | Unity AR & Bridge | Unity (AR Foundation / ARCore / New Input System) & Android Studio | ARCore 바닥/벽면 인식, 1회 바닥 높이 확정(`CalibratedFloorY`)·`±2cm` 미세 보정, 앵커링 조작, UaaL AAR 익스포트 및 IPC 양방향 통신 브릿지, `ARRuntimePerformanceGuard` [`SFR-002`, `SFR-004`, `PER-001`, `QUR-001`, `COR-001`] |

> [!NOTE]
> **최종 확정 범위 (In / Out of Scope):**
> - **핵심 구현 범위 (`SFR-001`\~`SFR-007`, 비기능 4종):** 100% Serverless On-Device 로컬 오프라인 독립 구동(`COR-001`).
> - **최종 제외 범위 (Out of Scope):** 가구 가동 부위 개폐 시뮬레이션(`!FR-04`), Tripo AI 2D 이미지 기반 3D 메시 생성(`SFR-008`), 외부 클라우드 DB 및 회원 계정(로그인) 서버.

## 2. 모듈 간 데이터 통신 규격 (JSON 사전 합의)

> [!IMPORTANT]
> 최주환(Android) $\rightarrow$ 진승호(Bridge) $\rightarrow$ 김기현(Unity)으로 전달되는 핵심 데이터 모델입니다. 이 규격을 확정해두면 세 사람이 각자 독립적으로 개발을 진행할 수 있습니다.

### [Android -> Unity] 가구 치수 전송 규격 (`FurnitureConfig`)
* **호출 방식:** `UnityPlayer.UnitySendMessage("ARBridgeManager", "OnReceiveFurnitureData", jsonString)`
```json
{
  "name": "원목 단독 책상",
  "width": 1.20,
  "depth": 0.60,
  "height": 0.75,
  "unit": "meter"
}
```

### [Unity -> Android] 충돌 상태 피드백 규격 (`CollisionEvent`)
* **호출 방식:** JNI 콜백 함수 `OnCollisionStateChanged(boolean isColliding)`
```json
{
  "isColliding": true,
  "target": "WALL",
  "message": "벽면 침범 발생"
}
```

## 4. 첫 팀 개발 협업 가이드 (팀원 안내용 요약)

1. **초반에는 각자 로컬에서 테스트하기:**
   - 안드로이드 담당자는 유니티가 없어도 가짜(Mock) JSON 로그를 찍으며 UI를 완성할 수 있습니다.
   - 유니티 담당자는 안드로이드 연결 전 에디터에서 임의의 $W, D, H$ 값을 인스펙터 창에 넣어보며 큐브 생성과 충돌을 먼저 테스트합니다.
2. **단위 통일 필수 ($\text{m}$ vs $\text{cm}$):**
   - 사용자 UI 입력은 $\text{cm}$ 단위이지만, **유니티 엔진의 1단위는 $1\text{m}$** 입니다.
